# V1 SQL, participação e identidade — Implementation Plan

**Goal:** substituir o protótipo com números inventados por um portal com identidade fornecida, participação persistida em SQL e administração auditável.

**Architecture:** Next.js App Router com SQLite em volume persistente e instância única. Rotas públicas nunca recebem dados identificáveis do banco. Módulos separados para banco, criptografia, sessões, consentimento, e-mail, conteúdo e exportação. Coleta pública permanece fechada até configurar controlador, privacidade, SMTP, proteção contra abuso e revisão de privacidade.

**Tech Stack:** Next.js, TypeScript, Tailwind, node:sqlite (Node >=22.16), Nodemailer, testes Node/Playwright.

## Sequência aprovada

- [x] Banco: schema versionado com participantes, tokens, sessões, auditoria, conteúdo e rate limits. Nome/e-mail cifrados; token armazenado apenas como hash; consultas parametrizadas.
- [x] Participação: nome, e-mail, município validado, consentimentos separados; confirmação por POST após abrir link; nenhum GET confirma apoio. Expiração, duplicidade, reenvio limitado, falha SMTP, revogação e contagem confirmada.
- [x] Admin: autenticação por senha scrypt, cookie HttpOnly/SameSite, expiração, CSRF por origem, logout, consulta paginada, CSV agregado e CSV pessoal com justificativa auditada. Sem exportação pública.
- [x] Certificado: código aleatório, noindex, emissão apenas para confirmado; verificação pública sem nome, dados pessoais somente com acesso autenticado do participante. Impressão com aviso de caráter simbólico.
- [x] Identidade: copiar logo original sem alterar o arquivo; tokens azul-marinho, azul-oceano, verde e dourado. Preservar composição aprovada; substituir contador fictício e afirmações sem fonte.
- [x] Conteúdo: navegação para páginas reais, fontes, estudos e notícias com vazio honesto, publicação administrativa simples. Sem inventar acervo, legislação, estatísticas ou trajetória.
- [x] Testes: banco isolado temporário, nenhuma escrita no banco real; validação, duplicidade, confirmação, revogação, CSV injection, autorização, CSRF, falhas; QA desktop/mobile e build sem dev simultâneo.

## Dependências de lançamento

Nome do controlador e contato de privacidade, política de retenção aprovada, credenciais SMTP, chaves Turnstile e autorização do retrato. O administrador local pode operar antes da coleta; os dados de teste nunca entram no banco publicado. PostgreSQL fica necessário ao migrar para múltiplas instâncias/hosting sem disco persistente. Não se declara a plataforma completa nem coleta pública pronta enquanto essas dependências não estiverem resolvidas.
